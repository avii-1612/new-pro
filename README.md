# E-Commerce Sales & Customer Analytics

End-to-end data analytics project on e-commerce transaction data, covering sales performance, profitability, and customer behavior. Built with Python, SQL, and Power BI.

## Overview

This is meant to simulate what a Data Analyst actually does day to day: take a messy raw export, clean it up, explore it, query it in SQL, segment the customers, and turn all of that into something a stakeholder could actually use.

## Business problem

An e-commerce company wants to know which products and categories are actually making money, which regions and customer types matter most, whether discounting is helping or hurting profit, and who its most valuable customers are. This project works through all of that using the data.

## Objectives
- Clean and prepare a raw transactional dataset
- Explore sales, profit, product, and regional performance
- Write SQL queries covering common analytics use cases
- Do customer-level analysis including RFM segmentation
- Build a Power BI dashboard
- Turn the findings into concrete recommendations

## Dataset

`data/raw/ecommerce_raw.csv` is a synthetic dataset (not real company data, generated by me for this project) of about 18,000 order lines from Jan 2023 to Dec 2024. I built it with some controlled randomness so it has realistic seasonality, category-level margins, and repeat customer behavior. I also deliberately threw in some mess, duplicates, missing values, invalid entries, inconsistent casing, bad date strings, so the cleaning step has real problems to solve instead of being a formality.

Fields: Order_ID, Order_Date, Customer_ID, Customer_Name, Product_ID, Product_Name, Category, Sub_Category, Region, State, Quantity, Unit_Price, Sales, Discount, Cost, Profit, Payment_Mode, Customer_Type, plus a few columns added during cleaning (Revenue, Profit_Margin, Month, Quarter, Year).

`data/raw/generate_dataset.py` is the script that generates it. Run it again if you want a fresh sample.

## Tech stack
Python (Pandas, NumPy), Matplotlib, Seaborn, SQL, Power BI, Jupyter Notebook.

## Data cleaning

Done in `notebooks/ecommerce_analysis.ipynb`, Parts 1-3:
1. Loaded the raw CSV, checked shape, dtypes, summary stats
2. Found and removed 150 fully duplicate rows
3. Fixed inconsistent Category casing ("ELECTRONICS" to "Electronics")
4. Dropped 40 rows with invalid Quantity or Unit_Price (data entry errors)
5. Fixed or removed 25 malformed date strings, then converted Order_Date to a real datetime
6. Filled missing text fields (Customer_Name, Payment_Mode, State) with "Unknown", missing Discount with 0
7. Added calculated columns: Revenue, Profit_Margin, Month, Quarter, Year
8. Flagged (didn't blindly delete) statistical outliers using IQR, since a big order could just be a bulk purchase
9. Final clean dataset: 17,935 rows, 0 missing values, saved to data/cleaned/ecommerce_cleaned.csv

## EDA

Covered in Part 4 of the notebook: headline KPIs, monthly revenue/profit trend, category and sub-category performance, top and bottom 10 products, regional performance, customer type performance, discount vs profit, quantity vs revenue, and repeat vs new customer revenue share. Each chart has a short note on what it shows and why it matters.

## SQL analysis

`sql/analysis_queries.sql` has 18 queries covering total sales/profit, monthly trends, top products/categories/customers, regional sales, AOV, customer segmentation with CASE, repeat customers with a CTE and subquery, low-profitability products with HAVING, profit margin by category, and year-over-year growth with LAG(). All of them were actually run against the cleaned data to make sure they work.

## Power BI dashboard

`dashboard/POWERBI_BUILD_GUIDE.md` has the full build spec: data source, DAX measures, layout, and slicers. A .pbix file can only be saved from Power BI Desktop itself, so instead of faking a binary I wrote a guide that gets you there in about 20-30 minutes.

## Key insights

Full writeup in `reports/business_insights.md`. Short version:
- Electronics is 63% of revenue but has the lowest margin (12%) of any category
- Beauty (45%) and Fashion (39%) are the most profitable per rupee sold
- Margin drops from 35.4% with no discount to 12.3% at 21-30% discount
- Returning customers bring in 58% of total revenue
- Repeat purchase rate is 93.47%
- December is the peak month, May-June is the low point

## Recommendations

Full list in `reports/business_recommendations.md`. Short version: cap discounts around 10%, protect Electronics margin through bundling, put more marketing behind Beauty and Fashion, build a loyalty program for the high-value RFM segment, and stock up ahead of Q4.

## How to run it

```bash
# install dependencies
pip install -r requirements.txt

# regenerate the raw dataset if you want a fresh sample (optional)
python data/raw/generate_dataset.py

# open the notebook (already has outputs saved, but you can re-run it)
jupyter notebook notebooks/ecommerce_analysis.ipynb

# run SQL queries against the cleaned CSV, e.g. with SQLite
python -c "import pandas as pd, sqlite3; df=pd.read_csv('data/cleaned/ecommerce_cleaned.csv'); conn=sqlite3.connect(':memory:'); df.to_sql('sales', conn, index=False); print(pd.read_sql(open('sql/analysis_queries.sql').read().split(';')[0], conn))"

# build the dashboard by following dashboard/POWERBI_BUILD_GUIDE.md
```

## Interview questions I'd expect, and how I'd answer them

**Walk me through your cleaning process.**
I started by profiling the raw data, shape, dtypes, missing values, duplicates. Found 150 duplicate rows, 40 with invalid quantity or price, and inconsistent category casing. Removed the duplicates and bad rows, standardized casing, converted dates properly, and filled the rest of the missing values with "Unknown" instead of dropping otherwise-good rows.

**Why didn't you just delete the outliers?**
I checked Revenue outliers with IQR and got about 13% of rows flagged. Deleting all of those automatically would've thrown out legit bulk orders and premium electronics purchases, which are realistic in e-commerce. I flagged them instead of removing them.

**What was your most interesting finding?**
Electronics drives the most revenue but has the lowest margin (12%), while Beauty and Fashion have the highest margins (45% and 39%) on much smaller revenue. I'd protect the Electronics margin through bundling and push more marketing budget toward Beauty and Fashion since spend converts to profit more efficiently there.

**How did you approach customer segmentation?**
RFM: recency, frequency, monetary. Scored each customer 1-4 by quartile on each, averaged the scores, and bucketed people into High/Medium/Low value. Simple, explainable, and directly usable by a marketing team.

**How did discounting affect profitability?**
I bucketed orders by discount band and compared average margin per band, both in Python and with a CASE statement in SQL. Margin dropped from 35.4% at no discount to 12.3% at 21-30%. Deep discounts should be used selectively, not as a routine tactic.

**What SQL concepts did you use?**
GROUP BY and aggregates for the KPIs, CASE for customer segmentation, subqueries and CTEs for the repeat customer analysis, HAVING to filter out low-volume noise in the low-profitability query, and window functions (LAG, running SUM) for year-over-year growth and cumulative revenue.

**What would you improve given more time?**
Move to a real star schema instead of a flat CSV, add a basic next-quarter forecast, and turn the cleaning notebook into a reusable pipeline script.
